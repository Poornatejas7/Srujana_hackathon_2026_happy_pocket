# Comprehensive Specification: Indian Banking & UPI Transaction Data (NPCI Standards)

In India, every electronic transaction (UPI, IMPS, NEFT, RTGS, NACH Mandates, POS Card Swipes) follows strict guidelines governed by the **Reserve Bank of India (RBI)** and the **National Payments Corporation of India (NPCI)**.

This guide outlines **what data is stored**, the **exact anatomy of narration strings**, and **how to reliably extract every component**.

---

## 1. The Anatomy of an Indian Transaction Narration

Every bank statement in India packs multiple metadata fields into a single line or block (the "Narration / Details" column).

### A. UPI (Unified Payments Interface) — Most Common

**Standard NPCI Format Pattern:**
```
[Txn Mode]/[Direction]/[12-Digit RRN]/[Beneficiary or Merchant]/[Bank IFSC Prefix]/[VPA Handle]/[Remark or Mandate]
```

**Real Examples from Your Bank Statement:**
```text
WDL TFR UPI/DR/203821706198/MEESHO T/UTIB/MEESHOONLI/UPI 0097695162091 AT 40184
WDL TFR UPI/DR/103643355290/NETFLIX/H DFC/netflix.bd/Execu 0097694162092 AT 40184
DEP TFR UPI/CR/656771804358/KOTRESH C/CNRB/mykotresh-/UPI 0097735162098 AT 40184
```

#### Field Breakdown:

| Field Name | Example Value | Description & Extraction Value |
| :--- | :--- | :--- |
| **Transaction Mode** | `WDL TFR` or `DEP TFR` | `WDL TFR` = Withdrawal Transfer (Debit)<br>`DEP TFR` = Deposit Transfer (Credit). |
| **Direction** | `DR` or `CR` | `DR` = Money sent out<br>`CR` = Money received / refund / payroll. |
| **NPCI RRN (Retrieval Reference No.)** | `203821706198` | **The unique 12-digit transaction identifier** generated by NPCI. Guaranteed unique across all Indian banks for that calendar year. Essential for reconciliation. |
| **Beneficiary / Payee Name** | `MEESHO`, `NETFLIX`, `KOTRESH C` | Registered name of the merchant, business, or contact. |
| **Acquiring Bank Code** | `UTIB`, `HDFC`, `CNRB`, `SBIN`, `ICIC` | 4-letter RBI Bank Identifier (matches the first 4 characters of the bank's IFSC code). Example: `UTIB` = Axis Bank, `CNRB` = Canara Bank. |
| **VPA (Virtual Payment Address)** | `MEESHOONLI`, `netflix.bd`, `mykotresh-` | The handle before `@upi` / `@okaxis` / `@oksbi`. Tells you if it's an app, merchant, or personal VPA. |
| **User Remark / Mandate Flag** | `UPI`, `Execu`, `Mand`, `Paym`, `Sent` | `Execu` / `Mand` indicates **AutoPay Recurring Mandate** (e.g., Netflix, Google Play, SIPs). `Sent` / `Paym` indicates manual peer-to-peer or bill payment. |
| **Terminal / CBS Audit Trail** | `0097695162091 AT 40184` | Internal Core Banking System (CBS) journal sequence number + branch code (`40184`). |

---

### B. IMPS (Immediate Payment Service)
Used for instant 24x7 bank-to-bank account transfers without UPI:
```
IMPS/P2A/329182910291/KOTRESH C/HDFC0001234/Personal
```
- `P2A` (Person-to-Account using Account + IFSC) or `P2P` (Person-to-Person using MMID + Mobile).
- 12-digit RRN: `329182910291`.
- Payee Name & Target IFSC: `HDFC0001234`.

---

### C. NEFT & RTGS (National Electronic Funds Transfer)
Used for larger payments, salary payrolls, and vendor settlements:
```
NEFT/N102938102938/TECH CORP SALARY OCTOBER/SBIN0040184
```
- UTR (Unique Transaction Reference): Starts with `N` (NEFT) or `R` (RTGS) followed by 16 alphanumeric characters.
- Beneficiary Organization: `TECH CORP SALARY OCTOBER`.

---

### D. NACH / e-Mandate (ECS Auto-Debits)
Used for Mutual Fund SIPs, Loan EMIs, and Insurance premiums:
```
ACH/UTI MUTUAL FUND SIP/UMRN102938475892/DR
ACH/HDFC BANK HOME LOAN EMI/UMRN992817263541/DR
```
- `UMRN` (Unique Mandate Reference Number): 20-digit alphanumeric ID assigned by NPCI when you sign an AutoPay mandate.

---

### E. POS / Card Swipes (Debit & Credit Cards)
```
POS/SWIGGY BANGALORE/041026/1830/XX4192
ECOM/AMAZON PAY INDIA/041026/1420/XX1008
```
- `POS` (Physical swipe / tap) or `ECOM` (Online card purchase).
- Merchant location (e.g., `SWIGGY BANGALORE`).
- Date (`041026`), Time (`1830`), and Masked Card Digits (`XX4192`).

## 2. Common Fields Present in Every Indian Bank Record

| Field Name | Type | Always Present? | Description / Extraction Method |
| :--- | :--- | :--- | :--- |
| **Txn Date** | Date (`DD/MM/YYYY`) | **Yes** | Date transaction was initiated. |
| **Value Date** | Date (`DD/MM/YYYY`) | **Yes** | Date interest and clearing actually settled. |
| **Transaction Amount** | Decimal (`1234.56`) | **Yes** | Net value transferred in INR (₹). |
| **Balance** | Decimal (`12345.67`) | **Yes** | Post-transaction ledger balance. |
| **Reference / RRN / UTR** | String (12-16 chars) | **Yes** (99% electronic) | Unique identifier for deduplication and matching. |
| **Cheque / Chq No.** | String | No (Only physical cheques) | 6-digit cheque number. |
| **Transaction Channel** | String | **Yes** | `UPI`, `IMPS`, `NEFT`, `RTGS`, `ATM-WDL`, `POS`, `INB` (Internet Banking), `MB` (Mobile Banking). |

## 3. How to Extract & Process This Easily in Code

### The Universal Regex for Indian UPI Narrations
```python
import re

UPI_REGEX = re.compile(
    r'(?P<mode>WDL\s+TFR|DEP\s+TFR)?\s*'
    r'UPI/(?P<direction>DR|CR)/'
    r'(?P<rrn>\d{12})/'
    r'(?P<payee>[^/]+)/'
    r'(?:(?P<bank>[A-Za-z0-9]{4}))?/?'
    r'(?:(?P<vpa>[^/]+))?/?'
    r'(?:(?P<remark>[^\n\r]+))?',
    re.IGNORECASE
)

sample = "WDL TFR UPI/DR/203821706198/MEESHO/UTIB/MEESHOONLI/UPI"
match = UPI_REGEX.search(sample)

if match:
    data = match.groupdict()
    print("Mode:", data['mode'])          # WDL TFR
    print("Direction:", data['direction'])# DR (Debit)
    print("RRN:", data['rrn'])            # 203821706198
    print("Payee:", data['payee'])        # MEESHO
    print("Bank:", data['bank'])          # UTIB (Axis Bank)
    print("VPA:", data['vpa'])            # MEESHOONLI
    print("Remark:", data['remark'])      # UPI
```

## 4. Key Rules for Financial Visibility & Expense Discovery in India

1. **Self-Transfer Deduping:**
   - Look for the user's name in `payee` (e.g. `KOTRESH C`, `mykotresh-`) or same-day cross-account transfers.
   - Tag as `INTERNAL_TRANSFER` $\to$ Set net living expense to ₹0.00.
2. **Refund Pairing:**
   - When a `CR` transaction has `MEESHO`, `AMAZON`, `FLIPKART`, or `ZOMATO` in `payee`, match it with the earlier `DR` to that merchant and net the difference.
3. **Recurring / Mandate Detection:**
   - When `remark` contains `Mand`, `Execu`, or `AutoPay`, flag it immediately as a **Recurring AutoPay Mandate** (e.g., Netflix, Google Play, SIPs).
4. **P2P Split Reconciliation:**
   - Payments with person names (e.g., `Dawood A`, `Harsha`, `Veerabhadrappa`) with remarks like `Sent` or `Paym` are peer transfers, not commercial retail expenses.

## 6. Will the MCC Code Be Present in Data from RBI Account Aggregator vs. Parsed Database?

Here is the exact technical breakdown of data availability across both data sources:

### A. When Ingesting via RBI Account Aggregator (AA Framework)
* **Savings / Current Bank Accounts:**
  - **In raw `narration`:** Banks transmit the standardized NPCI text string (e.g., `UPI/DR/203821706198/MEESHO/UTIB/...`).
  - **In AA Structured Metadata:** Under the official **ReBIT (Reserve Bank Information Technology) Schema** (`version: 1.1.3`), the `Transaction` entity contains:
    ```json
    {
      "txnId": "203821706198",
      "amount": "450.00",
      "type": "DEBIT",
      "mode": "UPI",
      "narration": "UPI/DR/203821706198/BLINKIT/AXIS/blinkit.groceries@axisbank",
      "reference": "203821706198",
      "currentBalance": "39860.00",
      "transactionTimestamp": "2026-10-25T11:58:00+05:30",
      "merchant": {
        "mcc": "5411",
        "name": "Blinkit Commerce Pvt Ltd"
      }
    }
    ```
  - **Availability:** If the bank (FIP) has implemented ReBIT v1.1.3+ with merchant enrichment, the `mcc` field is populated. If the bank provides legacy basic schema, `mcc` may be `null`, but the registered trade name and VPA are **guaranteed** in `narration`.

* **Credit Card Statements via AA:**
  - **100% Present.** The Credit Card canonical schema explicitly enforces the `mcc` 4-digit code for every merchant charge.

---

### B. When Ingesting via Parsed Bank Statements (PDF / CSV / Scraped DB)
* **In Savings / Current Account PDF Statements:**
  - **The 4-digit number is generally NOT printed as a separate column** on passbooks due to 30-character print line limitations.
  - **HOWEVER, the data is still fully identifiable:**
    1. The **Registered Trade Name** (e.g., `ZUDIO`, `BLINKIT`, `INDIAN OIL`) is embedded in the CBS narration.
    2. The **VPA Handle** (e.g., `blinkit.groceries@axisbank` or `zudio.retail@hdfcbank`) reveals the merchant category.
    3. **Happy Pocket's Engine** ([`src/lib/engine.ts`](file:///home/kotresh/Code/HackthonHaked/src/lib/engine.ts)) matches these patterns directly to assign the exact ISO category without needing the raw 4-digit integer printed.

* **In Credit Card PDF Statements:**
  - **Often printed directly.** Many Indian banks (HDFC, SBI Card, Axis) print the 4-digit MCC in a dedicated column or bracket: `5651 - Zudio Bangalore`.

## 7. Why Merchant Category Codes (MCC) Are Critical for Financial Truth

The **Merchant Category Code (MCC)** is the **single most authoritative piece of metadata** in transaction processing. 

### How Happy Pocket Uses MCC as First-Class Ground Truth:
1. **Definitive Discretionary vs. Essential Separation**:
   - `MCC 5411` (Groceries) $\to$ **Essential Living Expense** (food you need to survive).
   - `MCC 5651` (Apparel & Textiles) $\to$ **Discretionary Shopping** (lifestyle spending).
   - `MCC 5812` (Restaurants) $\to$ **Discretionary Dining** (eating out).
   - Even if a merchant description is obscure (e.g. `SRI VENKATESHWARA ENT`), an `MCC: 5411` tag instantly tells the Happy Pocket engine with **99% confidence** that it is a grocery store, bypassing text ambiguity!

2. **Isolating Financial Noise (`MCC 6538` & `0000`)**:
   - Money transfers between bank accounts or peer splits carry `MCC: 6538` (Money Transfer) or `0000`.
   - The engine uses this code to **completely exclude the transaction from living expenses**, ensuring your net monthly living expense is never artificially inflated.

3. **Export Compatibility**:
   - Both the **CSV and JSON exports** now include the **NPCI MCC** column for full auditing, tax deduction matching, and external spreadsheet accounting.
